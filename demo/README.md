# RiskLesson — рабочее HTML-демо

Один самодостаточный HTML-файл (`risklesson-app.html`) — рабочее приложение управления
рисками, собранное поверх реальных данных и логики из `docs/prototypes/` и правил
из `docs/process_full_v4.md`, по прямому запросу пользователя.

**Это не финальный стек.** Согласно `CLAUDE.md`, продакшен-фронтенд — React + TypeScript +
`@nlmk/ds-2.0`, бэкенд — FastAPI + PostgreSQL (см. `backend/`). Этот файл — отдельная,
полностью клиентская версия для быстрой демонстрации бизнес-логики: состояние хранится
в `localStorage` браузера (осознанное отступление от ограничения CLAUDE.md
«не используй localStorage как основное хранилище» — оно относится к финальному приложению,
не к этому демо).

## Запуск

Просто открыть `risklesson-app.html` в браузере — сборка/зависимости не нужны.

## Что реально работает

- Вход по имени/фамилии → роль (Риск-менеджер / Владелец риска / Инициатор) → СПП `12-1111`.
- Инициатор — компактная форма подачи риска с AI-подсказками «Возможный дубль» /
  «Похожий урок» (клиентская эвристика по пересечению ключевых слов).
- Реестр рисков — 15 реальных рисков ЦГП-2, рабочие фильтры (категория/статус/поиск),
  паспорт риска со стаппером статус-конвейера, аудит-логом и мероприятиями.
- Оценка P (чек-лист из 3 вопросов) / I (1–3 с обязательным обоснованием при I=3) →
  RRA = P×I, 3 зоны (L/M/H), автоматический флаг эскалации при I=3.
- Матрица рисков — исправленная сетка **3×3** (в прототипе `workspace.html` была
  визуальная сетка на 5 колонок при данных 3×3 — именно об этом предупреждает
  `CLAUDE.md`: «не 5×5»).
- Карта взаимосвязей — ручные связи между рисками, объединение дублей с постатейным
  выбором значений (архивирует риск с `mergedIntoId`).
- Реестр уроков — 10 реальных уроков БВН, фильтр по хештегам, «Создать риск на основе
  урока» с реальным переносом полей.
- Календарь — события считаются из реальных плановых дат мероприятий (не захардкожены).
- Privacy Reports & Analytics — Executive Summary и AI-подсказки связей риск↔урок
  считаются из текущих данных на лету, а не зашиты как текст.

## Известные упрощения относительно `process_full_v4.md`

- `Action.plannedDate`/`forecastActualDate`/`cost` — текстовые поля (как в реальных
  данных: «июн.26», «Фазы 3, 4», «tbd»), не строгие даты/числа.
- AI-функции — клиентская эвристика (пересечение токенов), не настоящий вызов
  Anthropic API — в финальном стеке эту роль играет бэкенд.
- Пользователи — не отдельная сущность с ID, только текст «Имя Фамилия» из формы входа.
