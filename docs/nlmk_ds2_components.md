# NLMK Design System 2.0 (`@nlmk/ds-2.0`) — каталог компонентов для RiskLesson

> Источники: приложенный `Книга1.xlsx` (реальные примеры кода из Storybook) + `https://nlmk-group.github.io/ds-2.0/?path=/docs/components-accordion-info--docs`. Это НЕ визуальный референс для ручного повторения в CSS — это устанавливаемый npm-пакет `@nlmk/ds-2.0` с готовыми React-компонентами. Прототипы `workspace.html`/`RiskLesson · Вход.html` были нужны, чтобы зафиксировать логику и раскладку экранов на этапе обсуждения — финальная реализация в Claude Code должна использовать этот пакет, а не воспроизводить CSS-классы `.ws-*`/`.risk-card*` вручную.

---

## Ключевой компонент: Accordion — прямое попадание в «Аккордеон мероприятий»

```jsx
import { Accordion } from '@nlmk/ds-2.0';

const items = [
  { id: 1, title: 'Общая информация', content: 'Краткое описание процесса', initiallyExpanded: true },
  { id: 2, title: 'Требования', content: 'Список обязательных условий' },
];

export default App = () => <Accordion items={items} />;
```
GitHub: `nlmk-group/ds-2.0/tree/main/src/components/Accordion`

**Где использовать:** карточка риска в «Реестре рисков» — каждый риск как `item` аккордеона, `content` — таблица мероприятий (см. `process_full_v4.md`, Этап 5 «Структура аккордеона»). `initiallyExpanded` можно проставлять для рисков со светофором 🔴, чтобы просроченные сразу были видны развёрнутыми.

## Полный список компонентов из вложения — с привязкой к экранам

| Компонент | Что делает | Где в RiskLesson |
|---|---|---|
| **Accordion** | Раскрываемые секции | Аккордеон мероприятий в Реестре рисков (см. выше) |
| **Tabs** (+ `Tabs.Tab`, `Tabs.Icon`, `Tabs.Tooltip`, `hasBadge`) | Навигация по разделам, с бейджами и тултипами | Верхний уровень навигации workspace — 7 вкладок сайдбара; `hasBadge` — для бейджа «AI» на Privacy Reports & Analytics |
| **Status** (`color="error/success/warning/grey"`, `icon`) | Цветной статус с иконкой | Статус мероприятия (Выполнено/В работе/Планируется/Отклонено) и статус риска — вместо самодельных `.badge-pill` |
| **Legend** (`type="EDIT"`, `colorList`) | Цветовые метки с выбором | Легенда зон RRA (L/M/H) на Матрице рисков и в фильтре Реестра — вместо самодельных цветных квадратиков |
| **Filter** (`mode="multiselect"`, `filterTypeOptions`, `filterValueOptions`) | Фильтрация по типу/значению, подходит для шапки таблицы | Фильтры «Категория» / «Статус» в Реестре рисков и Реестре уроков — замена `<select>` |
| **FilterTip** (`isActive`, `size`) | Чип активного фильтра с удалением | Показ применённых фильтров над списком рисков |
| **MultiSelect** / **SimpleSelect** / **Select** / **Autocomplete** | Разные варианты выбора одного/нескольких значений, с поиском | Категория риска (SimpleSelect), Владельцы риска — теперь массив, значит **MultiSelect** (см. process_full_v4.md про мульти-владельцев), поиск риска/урока — Autocomplete |
| **DatePicker** | Выбор даты/времени, диапазоны | Плановый срок / Прогноз-факт срок мероприятия, дата пересмотра риска в Календаре |
| **Stepper** (`EStepState.filled/notFilled/disabled`) | Пошаговый индикатор с состояниями | Визуализация статус-конвейера риска (Идентификация → Анализ и оценка → Управление → Мониторинг и Контроль) прямо на карточке риска — нагляднее текстового badge |
| **SlideToggle** | Показ/скрытие блока по клику на заголовок | Альтернатива Accordion для более простых раскрывающихся блоков (например, «Полное описание риска» на детальной карточке) |
| **Checkbox** / **Radio** / **Switch** | Стандартные формы ввода | Чек-лист из 3 вопросов для расчёта P (Checkbox или Radio Да/Нет), переключатель ролевого фильтра |
| **Input** (`startIcon`) | Текстовый ввод с иконкой | Поле поиска в Реестре рисков/уроков (`startIcon={<IconSearchOutlined24/>}`) |
| **Pagination** (`withSelect`, `pageSizes`) | Постраничная навигация | Реестр рисков/уроков при большом количестве записей |
| **Avatar** (`userName`, `userSurname`, `imageSrc`) | Аватар пользователя | `.ws-user-avatar` в сайдбаре — сейчас это самодельный кружок с инициалами, заменить на `Avatar` |
| **Header** (`showNotification`, `showBack`, `breadcrumbs`, `Breadcrumbs.Crumb`) | Готовая шапка с заголовком, датой, уведомлениями, хлебными крошками | Топбар рабочего пространства — заменяет `.topbar`/`.ws-brand` |
| **NotificationItem** / **NotificationGroup** / **NotificationCard** | Панель уведомлений по колокольчику в Header, карточки с каскадной анимацией | Уведомления о просроченных мероприятиях и эскалации на комитет (I=3) — готовый паттерн вместо самодельного `.badge` в сайдбаре |
| **Comments** (`Comments.Item`, `.Author`, `.Content`, `.Actions`, вложенные ответы) | Список комментариев с ответами | Обсуждение риска / расхождений оценки прямо на карточке (сейчас в процессе это просто текстовое поле «Комментарий») |
| **Badge** | Простой бейдж, кастомизируется через `className`/`style` | Счётчики (например «N связей» на карточке риска, число уроков) |
| **Divider** | Горизонтальный разделитель с текстом | Разделение секций внутри Паспорта риска (Причина/Событие/Следствие vs блок РЕАГИРОВАНИЕ) |

## Что это меняет в решении по стеку

Раньше в `claude_code_prompt.md` фронтенд был помечен `[ЗАПОЛНИТЬ]` с примером «например React + TypeScript + Tailwind». Теперь это не открытый вопрос:

**Frontend: React + TypeScript + `@nlmk/ds-2.0`** — реальный корпоративный пакет, а не предположение. Использовать его компоненты вместо кастомных CSS-классов везде, где есть соответствие в таблице выше. Собственные компоненты пишутся только там, где в `@nlmk/ds-2.0` нет готового аналога (например: сама Карта взаимосвязей с SVG-холстом, Матрица рисков как сетка P×I, Knowledge Graph).

Токены цвета (`--steel-90`, `--steel-70`, `--steel-10`, `--spectrum-red-20/30/10`, `--spectrum-green-*`, `--spectrum-orange-*`) — это токены самого `@nlmk/ds-2.0`, они, судя по примерам, **не совпадают буквально** с токенами, которые уже в `workspace.html` (`--navy-900`, `--accent-600`, `--red-700` и т.д. — там своя, ранее подобранная палитра). Это нужно явно сверить: либо `workspace.html` использовал упрощённую самодельную палитру «в духе» ds-2.0 (правдоподобно, раз в комментариях там написано «согласовано с DESIGN.md проекта»), либо это два разных источника токенов. При переходе на настоящий пакет цвета должны браться из `@nlmk/ds-2.0`, а не из `--navy-900`/`--accent-600` — эти самодельные переменные были нужны только для быстрого HTML-прототипа без установки реального пакета.
