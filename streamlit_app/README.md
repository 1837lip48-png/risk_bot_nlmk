# RiskAssess Bot — Streamlit-версия

Реализация интерфейса на Streamlit по решениям `RiskAssess_Bot_checklist.xlsx`
(переход с HTML/JS-прототипа на Streamlit для MVP, п.6.2.1 ТЗ).

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py
```

## Что сделано по чек-листу

- **Матрица 3×3** в корпоративных цветах НЛМК (RRA = P×I, L/M/H).
- **Технологический стек** — Streamlit вместо статического HTML/JS.
- **Вход в систему**: только ФИО (серый плейсхолдер), роль (2 ключевые —
  Инициатор риска / Риск-менеджер), СПП только цифрами, без площадки и без
  пояснительного абзаца; светлая/тёмная тема; полная таблица 7 ролей из ТЗ
  (разд. 4) — сворачиваемый блок-справка, не отдельный админ-экран.
- **Профиль нового проекта** (F-04, разд. 9.1) — отдельный обязательный шаг
  при создании нового проекта: тип, отрасль, регион, контрактная модель,
  CAPEX-диапазон, длительность, стадия, long-lead, зависимость от уникальных
  поставщиков, логистика/регуляторика.
- **Confluence-импорт** — убран из интерфейса MVP.
- **Экспорт** — PDF/.xlsx вместо PPT (F-46), кнопки на риск-регистре.
- **Пул новых рисков** (F-13) с экспертными статусами (F-30): предложено /
  принято / изменено / отклонено / требует уточнения / недостаточно данных.
- **Проверка качества формулировки риска** (F-12) — показывает отсутствующие
  элементы (причина/следствие/владелец/материальность) и уточняющие вопросы.
- **Чат с ботом** (F-28) — вопросы о рисках/топ-рисках; при отсутствии
  данных бот явно сообщает об этом, а не «додумывает» (F-29).
- **RAG-индикаторы** в интерфейсе (например, «✔ источник проверен» в базе
  уроков) — сам контур chunking/embeddings/reranking (F-22–F-25) остаётся
  бэкенд-задачей вне рамок интерфейса.
- **Pre-mortem-сессии и админ-экран** — не реализованы (решение чек-листа:
  «убрать»).
- **Иконки в сайдбаре** сворачиваются в узкую колонку и раскрываются с
  подписями при наведении (чистое CSS-решение, без перезагрузки страницы —
  навигация через `st.session_state`, поэтому сессия/логин не сбрасываются).

## Осознанно не реализовано (ожидает решения/шаблона)

- **Модель полей `risks`/`lessons`** (разд. 8.2 / 8.4 ТЗ) — по чек-листу
  «будет представлен отдельный шаблон»; сохранена текущая, уже расширенная
  структура (причина/следствие/мероприятия) без произвольного добавления
  полей типа `trigger`, `impact_days`, `quality_status` и т.п.
- **Похожесть исторических проектов** (F-05/F-17/F-18, разд. 9.2, взвешенный
  score) — по чек-листу приоритет отдан похожим **урокам**, а не отдельному
  модулю similarity-score проектов; этот модуль не строился.
- **Реальный LLM/RAG-бэкенд** — чат и подсказки RAG в чек-листе явно
  описаны как контур, требующий отдельного решения "что в интерфейс, что в
  бэкенд"; в этой версии интерфейс демонстрирует UX и берёт данные только из
  уже загруженного реестра/базы уроков (без внешнего LLM-вызова).

## Данные

`data/risk_data.json` — реальные данные Программы ЦГП-2 (НЛМК): 15 рисков
топ-15 из 92 (с паспортами) и 84 извлечённых урока, перенесённые из
предыдущей HTML-версии прототипа (`../lessons_learned_interface.html`).
Методология (RRA 3×3, остаточная оценка по статусам мероприятий) — из
«Методики оценки рисков для мегапроектов» v2.2.
